PERSONAL PLANNING, TICKETING, AND TIME TRACKING — CONFIRMED DESIGN BRIEF

Purpose
A compact, robust personal desktop app for daily planning, personal project tickets,
scheduled work, and time tracking. Responsive layouts and team integration follow later.

Two visual concepts
A: Graphite and cyan. Tight rows, flat panels, thin dividers, compact technical utility.
B: Charcoal, muted amber, and sage. Softer panels, warmer accents, more breathing room.
Both concept sheets show Today, all-ticket Kanban, and an individual project's Map.
Screens contain fictional sample projects, tickets, events, and repository metadata.

Application shell
- Narrow persistent icon rail with tooltips and a visible active state.
- Home, Projects, Calendar, Time, future Code, and Settings destinations.
- Personal / Team switch in the upper-left region; separate scopes.
- Personal data stays private; future sharing and linking are explicit actions.
- Home has no contextual secondary sidebar.
- Projects has a collapsible contextual panel with project navigation, Schedule,
  Time tracker, and the user's projects.
- Persistent global timer and Quick Add remain accessible across views.

Today / Home
- Three pinned priorities, followed by due and overdue tickets.
- Day Agenda includes appointments, ticket work blocks, personal plans, and routines.
- Three upcoming major events have readable day countdowns; allow pinning a later event.
- Overdue work remains overdue until the user changes it.
- Reminders are enabled only for events or deadlines explicitly chosen by the user.

Projects and ticket views
- Projects opens an all-ticket Kanban with project filters.
- Choosing an individual project opens its Map; Kanban, List, and Details remain available.
- Projects are containers. Tickets are the actionable items within them.
- All views operate on the same ticket data, including the agenda and time tracker.
- Clicking a ticket opens a side inspector without losing the current board or map.
- A separate full Details view provides the broader ticket workspace.

Ticket structure
- Description, status, priority, project, labels/component, due date, estimate,
  tracked time, checklist, and dependencies are visible in the default inspector.
- Notes, activity, files, and code links can be accessed through secondary tabs.
- Support independent child tickets for steps requiring their own status or timer.
- Keep simple checklist items for smaller steps.
- Optional fields stay out of the way until needed.
- Default workflow: Inbox, Ready, Doing, Review, Done. Customize per project later.
- Blocked is a separate flag; dependency blocking is computed without changing status.
- Deadlines are distinct from calendar work blocks; one ticket can have several blocks.

Project Map
- Every added project ticket creates a card available to its map.
- Named subsections can use optional rules based on labels, component, milestone,
  or other ticket details, and allow manual organization.
- A ticket has one primary card; optional linked references can appear elsewhere.
- Tickets matching no rule appear in a visible Unsorted tray.
- Preserve manual placement until the user returns the ticket to automatic placement.
- Dragging between rule-based sections previews the classification field change,
  updates that field, and offers Undo.
- Section boundaries express containment. Directional arrows express dependencies.
- Goals, milestones, and optional related-ticket links are distinct relationships.
- Compact cards show ID, title, status, priority, and estimate; selection or zoom
  reveals further information.

Time and capture
- One active timer across the application; switch tickets with one click.
- Support editable manual entries and unassigned time.
- Quick Add captures a title first, then a ticket, event, or note type.
- Optional chips expand project, date, priority, and estimate fields.

Future Code / GitHub section
- Begin with a repository overview; files and diffs can follow.
- Show repository, branch, latest commit ID, release/tag, last update, checks,
  and linked issues or pull requests where available.
- Working-tree and synchronization status require a connected local checkout.
- Revision means Git branch/commit/release information, not a custom revision counter.

Generation
The two concept sheets were generated with the built-in image_gen tool using the
original Today, Mission Control, Flow Board, and Project Atlas concepts as references.
The exact prompt set is saved separately as combined-concept-prompts.txt.
